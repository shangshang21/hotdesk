# Hotdesk 写作管线重构评估（2026-10-01）

> 结论先行：**两版稿子分别死于两个相反的病。** v0.2.1 死于"自媒体味过浓导致失真"（把出票张数写成票价涨、编造群体动机）；Codex 修订版死于"严谨性高压把文风压塌"（满篇口径辨析、围绕飞猪数据组织全文、免责句堆叠，读起来像给平台做的数据解读软文）。
> 病根不在模型，在**提示词与校验的结构性失衡**：整条 write 链路 90% 是禁令（不能编造 / 口径 / 边界 / 拒收），几乎没有一条正面的文风要求；而素材的数字脊柱又来自商业平台通稿，"注明数据提供者"的严谨要求让品牌名成为文章骨架。

---

## 一、两版对比诊断

| 维度 | v0.2.1（用户：根本不行） | Codex 修订版（用户：围绕飞猪软广） |
|---|---|---|
| 开头 | 两边对照反差 ✅（"一边…另一边…"） | 学术劝导问句 ❌（"先别急着…真正值得问的是…"） |
| 品牌曝光 | 飞猪 3 次 | **飞猪 6 次，数据段全挂在"飞猪披露/飞猪说"上** ❌ |
| 文体 | 自媒体爆文腔（但形容词通胀：极其凶猛/暴增/飙升） | 分析师备忘录（每段一个"不能证明/不代表"） |
| 事实口径 | ❌ 标题"门票涨30%"——原文是**出票张数**增长，把单位写歪了 | ✅ 口径全对（还专门澄清了张数≠涨价） |
| 群体动机 | ❌ "年轻人集体抛弃""头也不回地扎进"（无证据断言） | ✅ 不再断言动机 |
| 具体场景 | 无（只有数据） | penguin 版有基诺山现场+利润分配数字 ✅，toutiao 版无 ❌ |
| 结尾站队 | ✅ "传统文旅还能靠门票收割多久？" | ❌ "你会继续下单，还是先把行程问明白？"（消费咨询腔） |
| 三平台差异 | 换标题+换词，结构雷同 | reader_question 机制起效了 ✅，但三个问题本身都没冲突感 |

**一句话：v0.2.1 有"钩子"没"底线"，Codex 版有"底线"没"钩子"。要的是两个都要。**

## 二、病根定位（按层）

### 1. 提示词层（主因）
- `instructions.write` 392 字里约 90% 是禁令与拒收条件，正面的文风要求只有"短句短段、口语、有立场"九个字，且没有任何可执行细节（开头怎么写、场景密度、结尾形态）。
- Codex 补的 `strategyInstructions.write` 又叠加了"写清判断能推到哪里""标题保持统计口径"等更多谨慎要求——**谨慎压死了灵动**。
- LLM 在"准确性高压 + 风格低压"下，理性选择就是最安全的文体：数据口径辨析文。这正是"围绕飞猪写"的直接成因。

### 2. 素材层
- research 的数字事实几乎全部来自新浪/中华网**转载的飞猪国庆通稿**。校验要求"注明原始数据提供者与适用范围"（这条本身是对的），但没有任何**品牌曝光控制**，模型只能反复点名"飞猪"。
- 三版正文合计飞猪出现 6 次、每处数据都挂"飞猪披露"→ 品牌成为文章骨架 = 软广观感。

### 3. 校验层
- `review` 明确写"只查硬伤，不挑文风"——**文风塌方无人拦截**。AGENT_RULES 第 1 条说"能抓住点击、又经得起核对"，后半句有 43 个测试盯着，前半句零校验。
- v0.2.1 的"门票涨30%"口径错误后来被 Codex 用一条**写死在 validate 里的正则**修补（`/门票\s*(?:涨|上涨|涨价)/`）——这是对着单一案例打补丁，不可泛化。

### 4. boundary 泄漏
- essence.boundary / causal boundaring 这些**后台严谨性数据**被模型原样搬进正文，每段出现一次"不能证明…""这是一组平台观察，不能直接推出…"。边界应该活在审核层，正文最多自然出现一次。

## 三、重构方案（本次实施）

### A. 文风：把"正面要求"写成可执行规则
1. 开头三句内必须出现具体反差/冲突（两边对照、现场细节或数字反差）；禁用定义式、劝导式、问句式开头。
2. 每篇至少一个具体的人/地点/现场细节（须有 Fact 支撑）。
3. 结尾必须是站队/吵架式问题，不是消费建议。
4. 形容词禁用表：极其、暴增、飙升、彻底、疯狂、集体抛弃、头也不回。
5. 口径与来源**首次出现标注一次**，后文用"平台数据""这组预订"指代。

### B. 品牌去中心化（硬校验，代码层）
- 新增 `brand_cap`：商业平台名（飞猪/携程/美团等，可配置清单）单篇合计出现 ≤ 1 次（标注一次即可，后文指代），超出拒收；**话题主角就是该品牌时豁免**（如"瑞幸联名翻车"话题）。
- 文章脊柱要求：围绕游客、现场、现象组织，不围绕平台数据报表组织。

### C. 免责句密度（硬校验）
- "不能证明 / 不代表 / 不等于 / 无法证明 / 不能直接推出" 单篇 ≤ 2 处，超出拒收；指令同步要求"判断边界全文最多自然出现一次"。

### D. review 增加文风体检（warning 级，不 block）
- 开头有无冲突、品牌是否超限、免责句是否堆叠、形容词是否通胀、结尾有无站队、是否围绕平台数据组织——记 warning 并给改法，硬伤规则不变。

### E. angles：reader_question 必须带冲突感
- 站队式 / 利益式 / 反差式，不生成学术问句。

### F. 配图：新增"配图需求单"（见下）

## 四、配图方案评估（第三个问题）

### 现状与痛点
- 现行 `collect_image` 只允许**原文正文里的图**（in_article=true）——防编造，方向正确，保留。
- 但原文图常"文不对题"：本次选中的是一张"原生旅游"**文字解释卡**（黄底+卡通小猪+拼音），与文章气质完全不符，还**自带飞猪品牌形象**，等于给软广感添柴。
- 新闻照片直接商用有版权风险；现有规则只提示"优先用平台编辑器自带正版图库"，**没有可操作的交付物**。

### 方案对比

| 方案 | 版权 | 匹配度 | 成本 | 结论 |
|---|---|---|---|---|
| A. 平台自带正版图库（头条/百家/企鹅编辑器内嵌） | ✅ 平台授权 | 中（需人工挑） | 零 | **主线，本次落地** |
| B. 免费商用图库 API（Pexels/Unsplash/Pixabay） | ✅ CC0 类 | 英文库对本土话题命中率低；风光类高 | 需免费 API key | 可选增强，后续接 |
| C. 原文图采集（现状） | ⚠️ 需注明出处 | 高（就是报道现场） | 零 | 保留，作证据链与备选 |
| D. AI 生图 | ⚠️ 平台标识风险 | — | — | 项目明确不用，维持 |

### 本次落地（A）
交付包新增 **`配图需求单.txt`**：每个图位给出
- 插入位置（标题后 / 第 X 段后）
- 画面要求（由已核对的 `article_relation` 生成：画面应有什么、什么情绪）
- **平台图库搜索关键词**（从话题标题与图位语义自动生成中文搜索词）
- 避雷项（不用文字卡冒充实景、不用带竞品品牌形象的图）

用户拿到需求单，在平台编辑器的正版图库里搜关键词即可——零版权风险、零 API 依赖，这是自媒体实际工作流里最顺的路。

## 五、验收标准
1. 全部测试通过（Node 24，`npm test`）。
2. 新增测试：品牌超限拒收与豁免、免责句密度拒收、配图需求单生成。
3. 用本话题（"原生旅游"）的旧数据重跑 write 校验：现有成稿会被新校验拦截（飞猪 6 次），证明规则真实生效。
